# 原文映射与保真导出

## 先索引，再转换 HTML

保留上传原件字节并计算哈希，在原件副本的 OOXML 结构上构建位置索引。索引与 HTML 转换共享块标识，或利用转换器提供的结构回调建立可靠映射。转换器若只输出 HTML 且丢失源位置，应补充结构映射；不能以相似文本匹配的第一个结果作为最终定位。

重复标题、空段、分页符、无文字图片和同文表格都需要稳定标识。正文块包括段落、表格、内容控件及其他支持的容器。遇到不支持的复杂容器，保留完整容器并显示具体能力限制，不静默丢弃。

HTML 是交互投影；Word 包是产物基准。允许 CSS 辅助还原纸张、字体、表格与段间距，但不能把渲染后的 HTML 当作下一次 DOCX 的输入。像素一致性必须针对实际文档及渲染环境核验，不以“转 HTML 成功”推断保真。

## 截取的前后位置

1. 用模板正文的完整首尾块构建 identifiedRange；范围包含表头、空白填充区、签章区及确属该模板的填写说明，排除下一模板标题。目录中的标题只能作为寻找线索。
2. 将有效锚点投影为 HTML 中的起止框线。用户拖动后反向解析为原件块边界，校验再写 effectiveRange。
3. 每次按 effectiveRange 从未修改的原件重建模板。保留独立映射，记录截取后块与源块关系，AI 替换位置同时可追溯到源位置。
4. 默认整表截取，包括合并单元格、嵌套表格和跨页续表。用户选择表内一部分时吸附整表并解释；只有实现了表格网格与合并关系修复后，才开放行/单元格截取。
5. 正文首尾之外仍可能有适用节属性、页眉页脚、编号起始值和关系依赖，必须一并解析。遇到跨边界书签、批注、域、修订、内容控件时，扩展至完整合法边界或明确报告不能处理。

项目已有 `.cursor/skills/tender-document-parser/scripts/extract_template.py` 可作为**完整正文块截取**候选，使用前读实际实现与测试，核对其 1-based 且包含结束块的参数与本技能 `[start,end)` 的换算。它不是 HTML 双向映射、AI 替换或多文档合并实现；不要仅因有这个脚本就声明整条能力齐全。迁移本技能到别处时该脚本不是必备依赖。

## 保留 DOCX 结构

在 OOXML 副本上进行局部裁剪/文本补丁，保留原 `pPr`、`rPr`、`tblPr`、`trPr`、`tcPr`、网格和合并关系、样式继承、编号、制表位、行距、边框、图片、页眉页脚及节属性。不要把段落/单元格整体赋值为纯文本后重建所有 runs。

单文档截取可以先保留原包资源，必须保证引用完整。检查输出是否携带未选正文的批注、脚注或嵌入对象；对不再被引用的敏感内容谨慎清理，并在清理后验证关系完整性，不能随便删掉共享依赖。

节属性常位于某节最后段落或正文末尾；从节中部截取时需取得该位置实际适用的页面尺寸、页边距、分栏、页眉页脚与编号设置。裁剪后的自动编号可能改变，需保持原有可见编号或明确报告差异。

## AI 内容替换

AI 接收用户填充内容、当前模板范围内的内容、字段上下文和允许修改的位置，返回结构化补丁，不返回整篇改写后的文档或任意代码。每条补丁至少包含：

- templateId、sourceHash、rangeRevision、fillRevision；
- 目标 part、blockId、run/textNode 范围或已识别空白字段位置；
- 操作 replace/insert、预期原文 before、待写入 after；
- fieldKey、用户填写内容中的证据、歧义/未匹配状态。

验证补丁位置在 effectiveRange 内，before 与实际内容匹配，插入点属于可填写位置。补丁不重叠，按倒序应用防止偏移漂移。AI 字段值只能来自用户输入或用户已提供材料中可核实的值，缺失则保持空白并提示。

占位符可能分散于多个 runs，匹配时建立字符到 run 的索引，写入时只改变命中的文字，保留非命中前后内容与样式。空格、下划线、制表位、表格空单元格和内容控件都可能是填充位；不能对全文所有空格、横线或人名做全局 replace。替换变长时继承字段原样式，检查溢出与分页变化，不自动缩字号或删文字掩盖问题。

同一词在采购人、投标人、法人、代理人位置可能语义不同，需要字段上下文区分。AI 无法确定时标记待补充。依法承诺文本、合同条款、金额、期限和评分要求不属于任意改写区；除用户明确给出相应替换意图，保留原文。电子签名/印章不由文字填充自动生成。

输出结果预览由**实际填充后 DOCX**重新渲染，不能仅在前端 HTML 改字后假定导出一致。保存替换报告，含命中、未命中、保留原值和失败项。

## ZIP 与合并

ZIP 包含本次有效集合每个模板的实际 DOCX，目录和文件名清理 Windows 保留字符/设备名，截断过长名称并用稳定 ID 消歧。名称不得形成绝对路径或 `..` 路径。使用顺序前缀保证解压后可见顺序一致。用于追溯的导出清单保存到 exports 目录，不必塞入用户要求“所有 DOCX”的压缩包。

合并使用能够处理 OOXML 关系的实现，不能仅将 `document.xml` 正文拼接。处理：

- 同名不同定义的 styleId、numId/abstractNumId 冲突；
- 图片和媒体名称、relationship ID、内容类型与引用重映射；
- 书签、绘图、批注、脚注/尾注、超链接等 ID 冲突；
- 分节、纸张方向、页边距、页眉页脚继承、首页/奇偶页设置；
- 模板边界分页及连续页码，避免无意插入空白页或改变原编号。

默认保留各模板自身版式，通过节边界连接；不统一全篇样式。跨模板自动编号和页码是否连续依据原件与用户意图，不能悄悄改写。所选合并库若丢弃后续文件页眉页脚或复杂部件，先解决或清楚报告合并不可用；ZIP 与合并分别报告成功，不用 ZIP 成功掩盖合并失败。

## 保真核验

结构核验：源哈希不变、首尾正确、未修改内容一致、表格网格与合并保留、媒体引用有效、节与编号可解析、补丁只作用于允许位置、所有结果与范围/填写版本一致。Word 能打开还不足以证明格式相同。

视觉核验：使用可用 Word/Office 渲染或已有文档阅读器，对照源范围、截取模板、填充结果和合并结果，查看字体、换行、表格、图片、签章空白、页眉页脚及跨页边界。填写长内容造成的自然换行须可见并可处理；未完成视觉核验时不要宣称“格式完全一致”。

PDF/OCR 转换可能丢失可编辑结构。图片嵌入 DOCX 虽可保留外观，却不能满足本技能逐字替换要求；这类文件应提示提供 DOCX 或走明确标注的转换校对流程。不能把其他解析技能的“原页图片 Word”降级策略套用到这里。
