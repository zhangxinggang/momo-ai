# 运行与验收

## 确定真实运行方式

先检查当前工程和宿主能力，选择能闭合全部交互的一条路径，不把技能文字当成已安装的服务。

先记录以下能力的真实实现位置、调用方式和可用状态；只有“组件/库已安装”不能算业务动作已接通：

| 能力 | 进入完整功能验收前需要的证据 |
| --- | --- |
| 上传并解析 | 页面收到真实文件，写入会话 temp 后触发转换；仅把文件加入聊天待发送附件不等同于自动解析 |
| DOCX → HTML 与选区 | 原文块索引、HTML 映射、用户选区回写和实际截取之间存在可执行调用链 |
| 目录与范围保存 | 增删改、排序、选区能落盘并在刷新后恢复，不能只有内存中的视觉变化 |
| 一键替换 | 按钮可调用真实模型并应用经校验的补丁；当前对话能生成文字不等于新页面有模型连接 |
| 两种导出 | ZIP 与合并 DOCX 各有实际处理函数、文件与下载入口；普通报告导出不能替代 |

任一必需能力缺失时先完成其实现再宣称完整交付；若本轮只做验证，记录具体缺口与未通过阶段。不能把未执行的检查标为通过。

- **独立本地工作台**：在会话 temp/app 下生成可运行页面与必要的本地处理服务。服务负责文件写入、DOCX 操作、AI 调用和导出，页面负责目录、选区及表单。优先使用项目现有依赖与已配置的模型能力；没有模型连接时可完成上传、选区、目录和导出基础链，明确显示“一键替换尚未连接 AI”，只询问缺失配置，不伪造成功。服务绑定本机地址，并为有副作用的本地请求检查来源/会话令牌，不开放任意文件路径或命令执行入口。
- **现有宿主中的工作台**：复用宿主已经提供且实际支持的组件、工具与动作续接。确保树拖拽、范围选择、弹框、处理结果和下载都有可调用能力；不存在的组件不能写成虚构 OpenUI。若必须扩展宿主才能满足需求，说明具体差距并按用户开发范围实现、更新架构文档；生成临时页面本身不授权无关产品改造。

截至本技能编写时对仓库的检查：

| 位置 | 可复用点与限制 |
| --- | --- |
| `packages/momo-tree/src/` | 树形组件和 adapter、改名/移动/创建等；现有拖拽侧重同级排序，不代表已满足全部跨层级商务模板操作 |
| `packages/momo-file-editor/` | 文档预览候选；需验证实际格式支持及位置映射能力，不假设预览组件提供 DOCX 截取 API |
| `apps/skill-platform/src/renderer/components/Chat/ChatGeneratedView/index.tsx` | HTML 走 sandbox srcDoc iframe，未直接提供落盘/AI 桥接，sandbox 也未声明下载权限；静态 HTML 不能自动获得宿主能力 |
| `apps/skill-platform/src/renderer/services/custom-tool/openui-library.ts` | 读取实际 schema 再选组件；SplitPane/FilePreview 可用于布局与文件预览，不等于完整树形选区编辑器 |
| `apps/skill-platform/src/renderer/components/Toolbox/CustomToolOpenUIPreview/WorkspaceComponents.tsx` | FileInput 默认将文件加入对话输入框，仍需发送/动作续接；SplitPane 当前仅有固定比例布局，不能假定存在分栏拖拽；FilePreview 是只读文件预览 |
| `docs/architecture/ai-chat-interface-mode.md` | 了解现有界面模式、动作续接、真实 sourceRef 准入和产物注册 |

代码会变化，每次实现时以实际源码为准。不要通过放宽 sandbox 或凭空构造 `window.electron`/`postMessage` 协议绕过缺失的能力。普通“导出可见文本/表格”的 ExportDocx 不适合保留源模板格式；需要下载真正截取/填充的 DOCX。

若使用宿主产物注册，注册的是 temp 中已存在的文件，预览使用工具真实返回的 sourceRef。宿主内部可能持久化聊天及产物快照，这是现有宿主行为，不应误称所有宿主内部数据均受 temp 目录控制；本技能控制的过程数据和交付文件仍全部在 temp。

## 无附件与演示

用户没有提供文件但请求生成工作台时，交付上传空状态和能工作的上传通路。为了测试可以在 temp 中创建明确标注“测试数据”的 DOCX，不能将它自动当作用户已经上传的文件或将测试公司信息展示为用户事实。用户只要求交互原型时可模拟处理，但所有模拟能力必须清楚标出，不能宣称满足真实保真导出。

## 必测用户路径

| 场景 | 可观察的通过标准 |
| --- | --- |
| 上传真实 DOCX | 真实 HTML、真实模板目录、原件哈希和双向位置映射均存在 |
| 重复标题/目录副本 | 点击节点定位正文模板，源中的相同名称不会定位错位 |
| 新增子级、重命名、拖拽、撤销/恢复 | 树层级和顺序正确，稳定 ID 与原文范围不串位，刷新后仍保留 |
| 调整起止 | 跨页、空段、图片和整表边界有效；切换回来、下一步和导出均使用新范围 |
| 非法选区/新空模板 | 指明无效项，不能直接生成空 DOCX 或把整份源文件当模板 |
| 下一步弹框 | 按钮位置正确，取消保留输入，全空不提交，多次点击不重复请求 |
| 一键替换 | 实际使用用户内容，跨 runs 占位符和空单元格可处理，未提供值保留并提示 |
| 结果页 | 左树右文档，延续最后选中项，右侧来自真实新 DOCX，切换可看所有模板 |
| 修改后重新生成 | 旧版本结果失效，旧任务晚返回也不能覆盖新范围/值 |
| ZIP | 解压后实际 DOCX 数量、名称、目录、顺序与导出清单一致，未点过的有效模板也包含 |
| 合并导出 | 按当前树顺序，图片/表格/编号/页眉页脚/横竖版节均保留且可打开 |
| 刷新/失败重试 | 磁盘恢复会话，错误不清空用户编辑，重试不重复追加内容 |

对 DOCX 处理代码添加有意义的结构/内容测试：原件不变、有效范围首尾、跨 run 替换、关系冲突、不同节的合并以及导出集合一致性。用浏览器验证关键交互链；保真声明另需实际文档视觉核验。只改技能文档时验证 frontmatter、引用路径和需求覆盖即可，无需启动整个工程测试套件。

验证报告保存在本轮 temp 中，分别记录“通过 / 失败 / 未验证”，每项附实际执行动作和证据路径。测试夹具与提取脚本的成功只证明对应局部能力；人工选定范围不能算自动识别通过，脚本改字不能算页面 AI 一键替换通过，DOCX XML 完整也不能算视觉保真通过。

## 交付说明

提供当前真实可用入口、启动方式（如需要）、会话 temp 路径和导出产物。记录已验证能力与尚未验证的格式/模型连接，不用“已完成”掩盖某个阶段尚是占位。页面源码和必要配置留在 temp/app，后续根据用户反馈修改同一会话。
