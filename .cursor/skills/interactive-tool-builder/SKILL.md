# 创建可复用交互工具

用户要求创建一个可重复使用的工具、生成器或处理页面时使用。先明确本次工具的输入、任务指令和交付内容；从已有上下文做合理选择，只有缺失内容确实阻碍实现时才提问。创建活动方案、文案、文档分析、数据整理等都遵循同一个执行契约，不复用其他业务的固定字段或结果模块。

## 通用执行契约

- 使用宿主已提供的 OpenUI 组件 schema，输出唯一 `openui` 围栏，第一条声明为 `root = ...`，所有引用必须完整声明。
- 有 AI 执行需求的工具以一个 `AgentTask(title, instruction, children, skill, steps, previewOriginal)` 为根，children 是 Form 组件数组。Form 中放适用的 Input、TextArea、Select、FileInput 和提交按钮，签名以宿主 schema 为准。没有文件需求时不添加上传字段。
- instruction 写清此工具如何处理用户后续提交的真实输入、如何组织结果和交付文件。可选 skill 仅引用已安装且适用的技能；无需技能时传 null。steps 是三个阶段名称，可按业务配置。
- 简单单文件工具使用 `FileTask(title, instruction, skill, description, accept, previewOriginal, steps)`，文件类型按任务设置。宿主负责原文件上传与真实 SourceRef、独立 Harness 会话、审批、追问、停止、失败重试、结果保存和原文件预览。
- 结果内容由用户提交后实际运行得出。初始页面不预填虚构分析、业务数据、产物 ID 或完成状态。结果中的表单按钮可以沿同一任务继续提问。
- 静态内容展示直接使用通用 OpenUI 组件。算法函数通过现有 AI 插件定义、校验、测试和注册链路接入；外部系统通过已有 API/MCP 能力接入，不在页面暴露凭证或伪造接口。

## 生成与验证

业务名称、字段、阶段标签、指令与结果模块全部放在工具定义或独立业务技能中。宿主不按工具名称或技能名分支。标书解析只是文档任务的一个示例，不是所有生成器的基础表单。

用户提供参考网站并要求复刻时，结合 `rea-page-rebuild` 的实际采集证据；参考图片按可见布局校准，未知行为明确保留为未知。HTML 沙箱适合视觉展示，AI 执行表单使用原生任务组件。

校验完整变量引用和位置参数，验证初始输入、执行中、停止/失败重试、结果、切换页面返回。工具箱内生成的定义由宿主校验保存；聊天中的工具保持为该轮独立界面，不能声称已保存到工具箱。
