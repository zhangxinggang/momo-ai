# 标书解析与界面生成

将用户上传的 PDF 或 DOCX 解析为带原文证据的中文分析结果。在 momo-ai 中选择此技能、上传文件、选择“界面”并发送“解析文件”时，完成文件分析后输出 OpenUI 界面。一级 Tab 固定，二级 Tab 和内容根据本次文件生成；业务布局和显隐规则由本技能定义，宿主基座只提供通用组件。

## 固定边界

一级 Tab 严格按以下顺序保留，不得增删、改名或因缺少内容而隐藏：

1. 基础信息
2. 技术参数要求
3. 潜在风险
4. 废标项
5. 投标人资格要求
6. 评标标准
7. 投标文件要求
8. 应标所需文件
9. 投标文件模板
10. 智能问答

不生成参考站点的左侧菜单栏、账户区、右上角图标/操作按钮（包括智能问答快捷按钮、重新解析、导出及其下拉菜单），不显示“内容由 AI 大模型生成”提示。保留十个一级模块导航、动态二级导航和分析内容区。分析内容占满页面，不显示“原招采文件预览”或右侧原文件栏。仅“投标文件模板”内用宿主通用 `FilePreview`（由 momo-file-editor 实现）展示实际截取的 Word，不自行绘制阅读器。十个一级 Tab 中的“智能问答”仍保留。

二级 Tab、表格表头、行项目、文本章节和模板条目均为动态数据。不要把参考文件的“投标人须知”“项目概况”等名称变成所有标书必有的二级 Tab。也不要复用参考项目名称、金额、联系人或条款。

## 读取与解析

技能资源使用真实技能目录的绝对路径；所有过程文件和产物写入宿主指定的 `temp/<sessionId>`，相对输出基于此目录，不能进入技能目录或项目目录后生成 work/outputs。

1. 找到本次上传的真实文件。未提供文件时请求上传；不得把演示数据当作解析结果。多文件属于同一项目时，合并分析并区分来源；不同项目默认分别生成结果。
2. 优先使用当前环境已有的文档读取能力。需要本地抽取时，运行 `scripts/extract_document.py`。它用标准库读取 DOCX，PDF 需要 `pypdf`；依赖缺失时可安装 `scripts/requirements.txt`，或改用环境内可用的 PDF 阅读能力。
3. 全文读取正文、表格、附录、表单及补充/澄清文件，保留页码或段落/表格位置。对扫描页、图像表格、疑似乱码和跨页表格用环境可用的视觉/OCR能力复核。抽取脚本只抽取文本，不是 OCR 或 AI 分析器。OCR 不可用时注明具体未读页，保留部分结果，不宣称解析完整。
4. 按 [references/analysis-rules.md](references/analysis-rules.md) 分析十个模块。先完成全文覆盖再归纳，不因上下文长度截断后半部分；长文件分章处理并合并证据。
5. 依照 [references/data-contract.md](references/data-contract.md) 生成数据。可运行以下命令创建一级 Tab 空骨架；然后由 AI 填充动态 sections，空骨架不是最终分析：

   ```text
   python <技能目录>/scripts/render_report.py --init analysis.json
   ```

## 动态组织规则

- 以文件实际章节、条款主题或评审维度组织二级 Tab。原文标题有意义时优先沿用；没有合适标题时根据内容归纳，避免大量无意义的单行 Tab。
- 每个二级 Tab 可以包含多个表格、正文块或原文模板。表头按该组内容设计，不强制统一字段数量。不同文档可以有不同的二级 Tab、表头、行数及内容形式。
- 同一个条件可能同时属于“资格要求”和“废标项”等模块；保留各自语义并指向相同原文证据。
- 文档未提及的金额、时间、参数、资格、分值或模板不得补造。缺失字段仅在有实际展示需要时标明“未明确”；整个模块没有内容时保持一级 Tab 并展示准确的空状态。
- 无法读取与原文未提及是两种不同状态，必须区分。冲突条款保留双方出处，列为待确认，不自行选一个。
- 一级 Tab 稳定，二级结构动态，是此技能的核心要求；除非用户明确修改规则，不把动态栏目改成固定清单。

## 界面模式：生成 OpenUI

界面模式必须读取 [references/openui-interface.md](references/openui-interface.md)，按其中布局、内容、交互及输出契约生成界面。直接在 Harness 中完成本技能的文件读取与分析，再输出唯一的 `openui` 代码块；宿主通用预览会将其显示为本轮界面，无需用户再确认或手动切换生成器。

- 使用宿主提供的组件定义和参数顺序；一级/二级导航均为可切换的 `Tabs`，不是文字清单。所有动态内容来自校验后的本次分析，不让通用生成器重新猜测业务结构。
- 各模块内容占满可用宽度，不生成原招采文件预览或右侧文件区域。“投标文件模板”按 [references/template-extraction.md](references/template-extraction.md) 从原件截取 Word 并核验版式，通过 `artifact_create` 注册后用返回的真实 `sourceRef.sourceId` 预览，禁止把模板渲染成纯文本或重排表格。
- 完成全文分析后可保留 `analysis.json` 供核验；界面模式交付的是可渲染 OpenUI，不以 HTML 文件链接或 JSON 骨架代替生成界面。
- 用户后续要求调整界面时，修改本轮 OpenUI，沿用真实源文件和证据。业务规则只在本技能及引用中维护，不要求宿主按技能名称分支或固化十个模块。

## 用户明确要求独立 HTML 时

使用 `scripts/render_report.py` 和 `assets/report.html` 渲染已校验的数据：

```text
python <技能目录>/scripts/render_report.py --data analysis.json --out 标书解析结果.html
```

独立 HTML 交付 HTML、对应 JSON 和同目录的 Word 模板；用户只要分析文本时遵从用户。此离线模板提供分析内容和 Word 链接，不含 momo 宿主组件，不得声称已接入宿主文档预览。

模板控制一级/二级 Tab 的布局和交互；AI 只生成数据，不临时重写整页 HTML/CSS。文本通过安全 DOM API 渲染，保留换行，不把标书里的 HTML 或脚本作为界面代码执行。模板本身无外部 CDN 或远程请求。

参考页面、2026-10-08 用户截图批注和界面边界见 [references/page-reference.md](references/page-reference.md)。截图用于布局参考，不复制其中项目事实或将二级栏目固化。

## 智能问答

用户针对已上传标书继续提问时，检索原文并给出带出处的答案；找不到依据就说明未明确，推断要单独标注。需要保存问答时，将问题、答案及证据添加到“智能问答”的动态内容并重新渲染。

OpenUI 或独立 HTML 展示问答记录；新问题由当前 AI 对话处理，不生成无后端能力的问答输入框。只有用户明确要求开发在线应用时，才另行实现文件上传、后端模型调用和问答接口。

## 完成前核验

- 十个一级 Tab 的名称与顺序完全一致；二级 Tab 和表头来自本次标书。
- 金额/币种/含税口径、日期/工作日或日历日、必须/不得/可以、评分公式/分值以及所有否决条款与原文一致。
- 关键结论可定位到源文件；风险推断与明确条款分开；缺失内容和未读内容没有被说成确定结论。
- 校验 JSON 事实及证据，逐个核对 Word 模板与原文版式，界面模式检查 OpenUI 组件、引用、十个一级 Tab、动态二级切换、长表格、空状态及截取 Word 的真实产物 sourceId；确认没有业务右上角操作按钮和 AI 提示。
- 界面模式输出唯一 OpenUI 代码块及简短覆盖说明；独立 HTML 返回结果文件。没有原文件时请求上传，不以参考截图数据生成解析结论。
