# 模块目录与提取边界

完整解析必须覆盖下列 10 个模块。标题措辞可以随采购方式变化（招标/询比/磋商/谈判/比选），语义归类不变。

## 1. `info_content` 基础信息

固定分组：

| 分组 | 必要内容 | 建议字段 |
| --- | --- | --- |
| 基础信息 | 项目名称、项目编号、采购人/代理机构、联系人、电话、地址、采购平台、标段/包件 | `信息类别`、`具体内容` |
| 投标人须知 | 文件获取、澄清、递交、开标、有效期、联合体、分包、踏勘、答疑 | `条款主题`、`具体要求`、`说明` |
| 项目概况 | 采购范围、建设地点、交付物、工期/服务期、质量目标、验收方式 | `项目要素`、`具体要求` |
| 关键时间节点 | 获取、答疑、澄清、递交、开标、演示、履约等绝对或相对时间 | `时间节点`、`具体时间`、`要求` |
| 价格与保证金信息 | 预算/最高限价、税率、报价口径、投标/履约/质保保证金、支付方式 | `费用项目`、`金额`、`形式要求` |

同时保留日期、时区、币种、含税/不含税、大小写金额和“日历日/工作日”的原文口径。相对时间不得擅自换算为绝对日期。

## 2. `tech_parms_content` 技术参数要求

每个可独立响应的主题输出一项：

- `name`：原文短标题；无标题时根据原文生成中性标题。
- `name_summary`：便于检索的短标题，不改变要求强度。
- `bid_content`：完整要求，保留数值、单位、接口、输入输出、兼容性、性能、安全、验收和交付边界。
- `quantity`、`unit_name`：仅在原文明确时填写。
- `ids`、`bid_raw_content`、`source`、`confidence`：证据与可信度。

按业务对象或功能拆分，不按每句话机械拆分。一个标题下存在多个独立验收条件时，应拆成多项并保留共同章节证据。

## 3. `latent_risk_content` 潜在风险

固定分组：

- `商务风险`：付款、垫资、账期、违约责任、知识产权、保密、验收、变更、工期、质保、运维、报价边界、责任失衡等。
- `控标风险`：可能造成不合理排他或竞争限制的品牌、专利、地域、业绩、证书、人员、接口、评分倾斜或唯一性条件。

字段为 `风险点`、`风险说明`，可增加 `风险等级`、`触发条件`、`建议复核动作`。使用 [风险与质量规则](risk-and-quality-rules.md)。

## 4. `invalid_bids_content` 废标项

逐项输出 `风险点`、`风险说明`、`原文`。覆盖但不限于：

- 资格、形式、响应性审查不通过；
- 签字、盖章、授权、密封、加密、上传、份数或格式不合格；
- 逾期、保证金、报价超限、异常低价、缺项漏项；
- 串标、围标、关联关系、虚假材料、重大偏离；
- 法律法规和文件明确列明的其他无效情形。

不得把普通建议或一般合同风险升级成废标项。

## 5. `qualify_content` 投标人资格要求

固定分组：

| 分组 | 建议字段 |
| --- | --- |
| 企业资格要求 | `资格要求`、`具体标准`、`证明材料要求` |
| 人员配置要求 | `人员角色`、`数量`、`资格/经验要求`、`证明材料要求` |
| 财务与信誉要求 | `要求类别`、`具体标准`、`证明材料`、`风险等级` |
| 资格性审查要点 | `审查项目`、`审查标准`、`检查方式`、`风险等级` |

区分“资格门槛”和“评分加分”。时间窗口、证书等级、业绩数量、人员社保、信用查询渠道及联合体条件不得省略。

## 6. `evaluate_content` 评标标准

固定分组：

- 技术部分评分标准：`评分因素`、`分值`、`评分规则或标准`。
- 技术评审要求：`评审因素`、`评审标准`、`评判要点`。
- 形式评审标准：`评审因素`、`评审标准`、`检查要点`。
- 资格评审标准：`评审因素`、`评审标准`、`证明材料要求`。
- 响应性评审标准：`评审因素`、`评审标准`、`要求`。
- 商务部分评分标准：`评分因素`、`分值`、`评分规则或标准`。
- 报价评分标准：`评分因素`、`分值`、`计算公式`、`基准价确定方式`。

原样保留公式、变量定义、区间端点、四舍五入规则、最低/最高有效价处理及主客观分。无法复原的公式必须告警。

## 7. `doc_preparation_content` 投标文件要求

固定分组：

| 分组 | 建议字段 |
| --- | --- |
| 投标文件组成 | `文件类别`、`核心组成部分`、`是否必交`、`格式要求` |
| 格式要求明细表 | `要求项目`、`具体标准`、`检查要点` |
| 电子投标要求表 | `技术要求`、`具体标准`、`准备工作` |
| 附件清单表 | `附件名称`、`获取来源`、`准备要求` |

重点提取目录顺序、正副本、纸张、装订、页码、签章、密封、命名、文件大小、格式、加密、CA、上传和备份要求。

## 8. `bid_submission_content` 应标所需文件

固定分组：

- 资格要求和符合性审查材料；
- 投标报价；
- 提交资料文件加分项；
- 其他需要提交的资料。

每项字段为 `资料名称`、`资料内容`、`说明`，并明确必交/条件性、签章主体、签署日期、份数、有效期、原件/复印件、用途和对应评分项。

## 9. `bid_template_content` 投标文件模板

识别文件内可直接填写或切分的响应函、授权书、报价表、承诺函、偏离表、业绩表等原始模板。每个目录项包含：

- `catalog_id`、`catalog_name`、`is_required`、`order`、`requirement`；
- `source`：文件名、章节、证据、提取模式和可信度；
- `template_file`：只有实际生成/切分成功时才填写文件名、格式、大小和预览；否则为 `null`；
- `warnings`。

只看到格式要求但没有原始空表时，不得伪称已提取模板。

## 10. `deviation_template_content` 偏离表模板

分别识别技术偏离、商务偏离、合同条款偏离。记录表名、列标题、必填列、填写规则、适用范围和证据。若原文要求“无偏离也须逐项填写”，必须保留。

## 跨模块关系

- 资格门槛可同时出现在 `qualify_content`、`evaluate_content` 和 `bid_submission_content`，各模块按用途表达，但引用同一证据。
- 明确废标后果同时进入 `invalid_bids_content`；相应准备动作仍进入 `doc_preparation_content`。
- 技术评分项不替代技术参数；评分点进入 `evaluate_content`，底层要求仍进入 `tech_parms_content`。
- 投标文件目录进入 `doc_preparation_content`；具体要准备的材料进入 `bid_submission_content`；原始可填写范本进入 `bid_template_content`。
