# AIM 自定义工具科技视觉生成规范

## 核心判断

默认生成具有现代科技感和高完成度的界面，但不要复制固定模板。科技感应由清晰的信息架构、精密的对齐、数据叙事、分层表面、克制的光效和可靠交互共同形成，而不是“全屏深蓝 + 到处发光”。用户明确提出的视觉方向优先于本规范。

## 先根据内容决定布局

生成前先判断页面要帮助用户回答的首要问题，并按业务结构选择布局：

- 实时监控：强调状态、异常和时间变化，可使用紧凑状态带、主趋势区和告警/排行侧区。
- 分析决策：让主图占据最大视觉权重，将筛选、对比和结论放在邻近区域；避免平均切成相同卡片。
- 指挥调度：以地图、拓扑、流程或主控制面为中心，左右布置资源与事件，不要用普通报表网格替代主场景。
- 质量/生产：围绕阶段、产线、良率、偏差和瓶颈组织模块；仪表、控制图和排行必须对应真实语义。
- 单任务工具：以任务表面为主，指标仅作辅助；不要为了“科技感”硬塞一屏图表。
- 内容或配置页：使用清晰分组、步骤状态、精密分隔和上下文提示，保持可读性优先。

在内部快速比较至少两种构图后再选择。允许非对称网格、主次跨栏、中心舞台、分栏工作台、纵向叙事或模块化自由拼接。模块尺寸由重要性和数据形态决定，禁止所有页面都生成“顶部标题、四个 KPI、下方 2×2 图表”的统一布局。

## 可迁移的视觉语法

三张参考界面呈现了两种可迁移但不可照搬的科技大屏语言：青色应急监测以发光地图为中心，金色金融监控以区域地图和趋势为中心，制造看板以 KPI、环图、仪表和排行形成生产叙事。共同方法如下：

- 深色分层底面承载高密度数据，背景可有极低对比度的网格、径向光晕或技术纹理。
- 当空间、网络、区域或流程关系是首要问题时，以地图、拓扑或流程作为中心舞台，左右信息舱只承担摘要、排行、告警和明细；不是此类任务时不要生造地图。
- 细描边、局部顶边高光、角标和内阴影界定面板；边界应清楚但不形成厚重发光盒子。
- 关键数值、主趋势和异常拥有明显的视觉优先级；标签、单位、时间和辅助刻度保持克制。
- 趋势线、环形占比、仪表、水平排行、状态图标等异构表达按语义组合，避免所有数据用同一种图。
- 顶部状态、时间或系统健康信息可形成仪表舱感，但只有业务需要时才出现。
- 青色方案适合应急、网络、能源和实时态势；金色/琥珀方案适合金融、价值、风险与区域经营。只选一个主能量色，避免青色与金色无目的混用。

## 色彩系统

默认使用暗色科技基调，并根据业务选择一个主色家族，不要让所有表面和文字都是同一种蓝：

- 海洋蓝示例：背景 `#031426`，深表面 `#071E36`，抬升表面 `#0C2B4A`，主强调 `#19D3FF`，次强调 `#3182FF`。
- 紫电青示例：背景 `#080D22`，表面 `#101936`，主强调 `#7C5CFF`，次强调 `#21D4FD`。
- 石墨青示例：背景 `#071715`，表面 `#0D2724`，主强调 `#2DE2B7`，次强调 `#69F0FF`。

正文用近白色而非纯白，辅助文字使用冷灰蓝。成功、警告、危险分别使用清晰但不过饱和的绿、琥珀和珊瑚红；语义色不能只靠颜色表达，还要配文字、图标或形状。一个页面通常只需要一个主强调色和一个次强调色，图表系列控制在 5–7 色内。

## 排版与数字

- 中文正文优先使用可靠系统字体；标题/数字可组合 `DIN Alternate`、`Bahnschrift`、`Inter`、`PingFang SC`、`Microsoft YaHei` 等可用字体，并提供安全回退。
- 数据使用等宽数字 `font-variant-numeric: tabular-nums`，单位与数值分层，避免单位抢占视觉。
- 建议层级：页面标题 22–32px，核心指标 28–48px，模块标题 13–16px，正文 13–15px，标签与刻度 11–13px。不要用大量低于 11px 的文字制造“专业感”。
- 标题、分隔线、编号和字距只在表达结构时使用，不做无意义装饰。

## 网格、面板与密度

- 使用 8/12/16/24px 等一致间距阶梯和 12 或 16 列流式网格；重要模块可跨栏，次要模块收紧。
- 页面应填满可用工作区但保持内边距；面板最小高度、图表比例和文本行数必须可控。
- 卡片至少有三层层级：背景、普通表面、重点表面。通过明度、边框和留白建立层次，不依赖重阴影。
- 同一行对齐基线；相邻图表的标题、图例和绘图区保持秩序。高密度不等于拥挤，必要时减少次要数据。
- 响应式时重排优先级而非简单缩小全部内容；避免固定宽度造成横向滚动。

## 图表与图标

- 趋势用折线/面积图；分类比较用横向或纵向条形图；组成用环形图或堆叠图；分布用散点/直方图；阶段用漏斗/流程；空间关系才使用地图或拓扑。
- 折线突出最新值、关键拐点和阈值；网格线低对比，坐标刻度简化但不能消失到无法读取。
- 环形图在中心显示最重要数值，并配直接标注；仪表只用于有明确范围和目标的指标；禁止装饰性 3D 饼图。
- 排行优先水平条，长标签不截断关键含义；异常项使用语义色或标记突出。
- 图表必须有真实示例数据、标题、单位和必要图例，不能只放空容器或无意义随机数据。
- 图标使用同一套 Lucide、Heroicons 或一致的内联 SVG，常规尺寸 16–22px；禁止用 emoji 充当功能图标。

## 光效、纹理和动效

- 背景可组合 1–2 个低透明径向渐变与细网格；面板可使用局部辉光、扫描高光或角标，但每个装饰必须服务于层级。
- 把大胆效果集中在一个标志性元素，例如主趋势光轨、中心拓扑、状态能量环或动态时间轴，其他区域保持安静。
- 动效用于解释状态：首屏分层进入、数字平滑更新、曲线绘制、告警脉冲或悬浮反馈。时长通常 150–400ms，并支持 `prefers-reduced-motion`。
- 禁止满屏霓虹、多个无意义脉冲、过重玻璃模糊、随机粒子和导致文本对比不足的渐变。

## HTML 实现约束

- 输出完整单文件，优先内联 CSS/JavaScript；不依赖宿主私有 API。除非环境明确提供，不依赖外部运行时或 CDN。
- 使用 CSS 变量集中声明颜色、间距、圆角、字体和阴影；`html`、`body` 与主容器应正确占满可用高度。
- 图表可用语义化 HTML、SVG 或 Canvas 实现；尺寸变化时重算或使用 `viewBox`，不得溢出 iframe。
- 可交互元素有明确 hover、active、focus 状态和指针反馈；表单有标签，文本与背景保持足够对比。
- 提供加载、空、错误和数据更新时间状态；不要让失败状态破坏布局。

## OpenUI 实现约束

- 只使用当前 OpenUI 系统提示中声明的组件和合法属性，不输出 HTML/CSS，也不虚构主题 API。
- 使用 Card/Stack/Text/Tag/Callout、表格和可用图表组合出清晰主次；让最重要的组件占据根结构中的主要位置。
- 关键、可配置或数据型组件必须赋给语义清晰且稳定的变量，便于用户点击配置和覆盖数据。
- 第一条声明保持为 `root = ...`；生成结束前检查 root、数组和父组件使用的每个变量都在同一份源码中声明，禁止残留 `aiFooter`、`mainChart`、`panel1` 一类占位引用。
- 在无法精确控制色彩和光效时，优先保证布局拓扑、图表选择、标签、单位、数据层级和状态表达，不能用重复卡片填满页面冒充设计。

## 禁止的模板化结果

- 不论需求都生成相同的四指标卡、折线图、饼图、表格组合。
- 所有卡片同宽同高、所有区域平均分配，主任务没有视觉中心。
- 用大面积纯蓝、密集发光边框、随机英文缩写或装饰线替代业务结构。
- 图表类型与数据关系不匹配，或为了丰富而堆叠无关图表。
- 直接复制参考图的标题栏、面板数量、图表位置和比例。
- 用 emoji、超小字、低对比文本、无对齐的数字或不一致图标破坏专业感。
- 使用浅灰网格背景、等宽三列大圆角卡片、ASCII 字符拓扑、随意中英混排、被逐字挤断的指标名称，或保留 `X-Axis`/`Y-Axis` 之类组件默认文案。

## 交付前质量门槛

- 一眼能看出页面的首要任务、最重要状态和下一步动作。
- 布局由业务内容决定，能够说明为什么主模块更大、为什么图表放在该位置。
- 色彩有主次和语义，暗色背景上文字、网格与曲线均清晰可辨。
- 数字、单位、标签、时间和图例排版一致；图表不是装饰。
- 1280px、1440px 等桌面宽度下稳定，较窄窗口能合理重排且不横向溢出。
- 动效克制并尊重减少动效设置；键盘焦点、错误和空状态可见。
